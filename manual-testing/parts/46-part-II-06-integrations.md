### 6.1 🔌 Results API keys

**Screen:** Configure → **Results API keys** · **Routes:** `GET /apikey/list`, `POST /apikey/add`, `DELETE /apikey/{credentialId}`; with a key: `GET /result/bytt/{ttNumber}`, `GET /result/bycustomer/{customerId}`, `GET /result/export.csv` · **Capability:** `apikey_manage`

- 🌟 **Commercial Presentation & Sales Pitch**: The ticketing system pulls the evidence itself — one ticket as JSON, a customer's tickets of a period as JSON, or a month of results as CSV — with a key scoped to the operator's own organisation, readable even if a renewal is late. The key is shown once and stored only as a hash.
- 📖 **User Guide & Operational Flow**: **Issue key** with a label and an optional expiry; copy it — it is never shown again. Your system sends it as `Authorization: Bearer <key>`. `GET /api/v1/result/export.csv?from=…&to=…` takes RFC 3339 times, at most 31 days apart; with no `from`, the day before `to` (default now). `GET /api/v1/result/bycustomer/{customerId}?from=…&to=…` gives a customer's tickets run in that period, newest first, each as `/result/bytt` gives one: the last 30 days when no `from` is given, any period otherwise, and the newest 200 a call, with `more` true when there were others - the count, not the period, bounds a call (customer decision, 29 October 2026), and the read stops at it through the customer's own index.

### 6.2 📤 Result export

**Screen:** Configure → **Result export** · **Routes:** `GET/PUT /export/target`, `POST /export/target/test`, `GET/PUT /report/settings` · **Capability:** `apikey_manage`

- 🌟 **Commercial Presentation & Sales Pitch**: Results delivered to the operator's own SFTP or FTPS server as CSV, every interval it chooses — no integration project. Nothing is lost: a failed delivery is retried with the same period, and each row carries a `result_id` so a file that arrives twice is recognised. The server's key is confirmed before anything is sent, and a saved password is only ever sent to the server it was entered for.
- 📖 **User Guide & Operational Flow**:
  - **Protocol:** SFTP (recommended), FTP over TLS, or FTP — with a clear warning that plain FTP is unencrypted.
  - **Server, Port, Username, Password** (or for SFTP a private key). Saved credentials are never shown again; leave the field empty to keep them, or tick *Remove the saved password*.
  - **Test connection** signs in, writes and removes a small file. For SFTP it shows the server's key: check it with whoever runs the server, then **Trust this key** and **Save**.
  - **Folder** and **Deliver every (minutes)** — 15 to 1440.
  - The status card says how the last delivery went: *Sent <file> with N results* (*with 1 result* for one), *Nothing new to send*, or *Not delivered: <why>*.
  - **Scheduled reports**, below, sends the network reports (§3.6) to the same server: the **Time zone** every report is cut in and every time in a result file is written in — the organisation's country's until one is chosen — and *Send each day's / week's / month's / year's reports*, each with how it last went and the period it sends next. It saves on its own **Save**; the result export need not be switched on.

### 6.3 🏢 Directory

**Screen:** Configure → **Directory** · **Routes:** `GET/PUT /ldap/config`, `POST /ldap/config/test`, `/ldap/groupmap/*` · **Capability:** `ldap_manage`

- 🌟 **Commercial Presentation & Sales Pitch**: Staff sign in with their existing network password over LDAP or Active Directory, and their directory group decides their PacketPulse role — after the second step, so a directory password alone still opens nothing. The owner always keeps a local password, so a directory outage cannot lock out the person who fixes it.
- 📖 **User Guide & Operational Flow**: Host and port (389 LDAP/StartTLS, 636 LDAPS), encryption, the CA certificate of your own authority, a read-only bind account, the base DN; then **Test connection** before enabling. **Group mappings** give each directory group a role.
  - **Who is looked up:** the person's PacketPulse email address up to the `@` is what replaces each `%s` in the **User filter**. Where directory account names match email addresses, `(sAMAccountName=%s)` (Active Directory) or `(uid=%s)` (OpenLDAP, FreeIPA) works; where they do not (staff numbers), search by mail: `(mail=%s@corp.example.com)`.
  - **Group filter:** each `%s` is the person's DN; for groups that list members by user name, `%u` is their user name — `(&(objectClass=posixGroup)(memberUid=%u))`. One of the two is required — without it every person would be in every group. Active Directory's `(&(objectClass=group)(member:1.2.840.113556.1.4.1941:=%s))` also follows nested groups. A filter may use a placeholder more than once: `(|(uid=%s)(mail=%s@corp.example.com))`.
  - Settings for Active Directory, OpenLDAP, OpenLDAP with `groupOfUniqueNames` or `posixGroup`, and FreeIPA are each proven end to end, using only the screen's fields, by `packetpulsego/pkg/ldapmicroservice/ldapservice/LdapDirectoryProducts_test.go`.
- 🧪 **Manual Testing Playbook**:

- ⚙️ **Developer Guide & Release Confidence**:
  - `packetpulsego/pkg/common/ldapclient/`, `packetpulsego/pkg/ldapmicroservice/`; the bind password is sealed like every secret; the directory is dialled through the directory policy (private yes; loopback only with `LDAP_ALLOW_LOOPBACK`, refused in production).
  - The connection is set up — LDAPS handshake, or StartTLS and its handshake — inside one deadline, the connection timeout; go-ldap puts none on a StartTLS handshake, so a middlebox that accepted the connection and went quiet used to hold a sign-in open indefinitely.
  - Only `invalidCredentials` (49) is a wrong password. A timeout, a dropped connection, or a domain controller answering `busy` / `unavailable` is *could not be reached* — for the person signing in and for **Test connection** — so an outage is never recorded as a failed sign-in.
  - 🔒 **Test connection** answers, and records as `last_test_result`, one authored sentence per kind of failure (`ConnectionTestMessage` in `packetpulsego/pkg/ldapmicroservice/ldapservice/LdapService.go`), never the raw error. Until October 2026 the raw error was recorded and `GET /ldap/config` returned it, so refused, timed out and the port could still be read. A result stored before then is shown as the generic failure.
  - Filters are filled by `fillFilter` in `packetpulsego/pkg/common/ldapclient/LdapClient.go`: every `%s` (not only the first, as `fmt.Sprintf` did), `%u` in a group filter, `%%` as a percent sign; each value escaped.
  - A user search answered with `sizeLimitExceeded` is the ambiguity (`ErrAmbiguousUser`), not an outage. Groups are read in pages of 500 with no cap on the count; a cap of 100 used to lose every group past it. Directory failures at sign-in are logged with their reason (*directory sign-in could not be completed*).
  - Coverage: `packetpulsego/pkg/common/ldaptest/` (an in-process directory that answers as OpenLDAP or Active Directory: DN matching, AD's matching rules and sign-in names, size limits and paging, per-connection identity and access rules, unavailable binds, stalled StartTLS, silent hosts), `packetpulsego/pkg/common/ldapclient/LdapCustomerDirectory_test.go`, `packetpulsego/pkg/ldapmicroservice/ldapservice/LdapDirectoryProducts_test.go`, `packetpulsego/pkg/usermicroservice/userservice/UserDirectorySignIn_test.go`, `packetpulseflutter/test/ldap_settings_screen_test.dart`.

### 6.4 📲 Field app sign-in

**Screen:** Configure → **Results API keys** → **Field app certificates** (whoever may issue Results API keys, `apikey_manage`) · **Routes:** `POST /partner/launch` (the field app's server, through nginx's partner site), `POST /user/signin/launch` (the phone), `GET /partner/certificate/list`, `POST /partner/certificate/add`, `POST /partner/certificate/{certificateId}/revoke`, `GET /partner/role/list` (the roles the registrant may give: those whose rights they hold) · **Access:** the organisation's owner keeps the register; the launch takes the registered certificate

- 🌟 **Commercial Presentation & Sales Pitch**: Field engineers sign in once, to the operator's own Android/iOS app. One tap on a ticket opens PacketPulse's Run tests page already signed in as them, with the TT number and customer filled in - no second password, no code. The app's server proves itself with a certificate that never leaves it; PacketPulse answers with a link that works once, for a minute. Each engineer is named as the app names them, so every test, report and Results API answer says who ran it.
- 📖 **User Guide & Operational Flow**: The app's team makes a key and certificate on its server (`openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes -days 397 …`) and sends PacketPulse's administrator the certificate only. Whoever may issue the organisation's Results API keys (`apikey_manage`; until 18 November 2026 the owner alone) pastes it under **Field app certificates**, names it, chooses the role the app's engineers get, and compares the SHA-256 fingerprint shown with the one the app's team reads out. The app's server then calls `POST https://partner.packetpulse.rummaan53.com/api/v1/partner/launch` presenting the certificate, with `engineer_id`, `email`, `name`, `tt_number` and `customer_id` - and, optionally, `return_url`, its own https page for the ticket - and opens the `url` it gets back at once. The phone sees PacketPulse's first screen at once (*Opening your ticket from the field app*), then Run tests with the ticket filled in under *Opened from your field app*, and - when the app sent `return_url` - **Back to the field app**, which returns in the same tab to the app's page, where the result appears by itself as soon as PacketPulse has graded it. The first launch for an engineer makes their account: it takes a place on the licence, has no password and cannot sign in on the website. Two certificates may be in use at once, so a renewal overlaps the old one; **Revoke** stops a certificate, and its unused links, from the next call. Field Eng App (`packetpulsetest/golang/fieldengapp/`) is a mock of such an app for trying all of this: `fiberapp-demo.rummaan53.com` live. It shows an engineer's day as a field app would: today's jobs by priority and SLA, a job's customer, line and timeline, the PacketPulse button, the result read back as a verdict, and **Close job**; a phone can install it on its home screen, so PacketPulse opens from it in the phone's in-app browser as from a real app. Each engineer's day is their own and begins afresh at sign-in, the SLAs counting down from then, so signing in again runs the demonstration again. Its sign-in is filled in with the first demo engineer, and a name under **Demo accounts** fills it with theirs; an answer from PacketPulse that is not PacketPulse's own error (an older server's bare 404) is told as what it means.

- ⚙️ **Developer Guide & Release Confidence**:
  - `packetpulsego/pkg/partnermicroservice/` (certificates, launches, links), `packetpulsego/pkg/usermicroservice/userservice/UserLaunch.go` (the session, through `newSession`), migration `0043_2026_11_18_partner_app_launch.sql`.
  - The certificate is read from `X-PacketPulse-Client-Cert` only on a connection from a trusted proxy (`apiratelimit.FromTrustedProxy`). nginx's partner site asks every caller for a certificate (`ssl_verify_client optional_no_ca`) and passes `$ssl_client_escaped_cert`; the ordinary site wipes the header in `location /api/` and refuses `/api/v1/partner/launch` - that alone: the certificate register under `/api/v1/partner/certificate/` is the web app's, through this site (refusing all of `/api/v1/partner/` shut it, live, on 18 November 2026; `PacketPulsePartnerNginxCheck.sh` now fails on that). PacketPulse pins the SHA-256 of the certificate itself.
  - A link's code is 32 random bytes; only its SHA-256 is stored, it lives 60 seconds, and the one statement that redeems it spends it - two phones with the same code open one session. A new link ends the engineer's earlier sessions before it opens one (`SessionRevokeAllForStaff` in `UserSignInLaunch`): an engineer the app signs in comes in no other way, so the newest tap is their one session. Revoking the certificate spoils its unused links.
  - `PARTNER_LAUNCH_APP_URL` is where links send the phone; empty takes no launches. `PARTNER_LAUNCHES_PER_MINUTE` is the app server's own limit.
  - Coverage: `packetpulsego/pkg/partnermicroservice/`, `packetpulsego/pkg/usermicroservice/userservice/UserLaunch_test.go`, `packetpulsego/pkg/staffmicroservice/staffdomain/repository/StaffAppEngineerRepositoryPostgres_test.go`, and the `fieldapp` suite, `packetpulsetest/golang/fieldengapp/` - Field Eng App and its stand-in for nginx's partner site, driven against the server.
